# 把值打出来，别去推它

找[模糊那条缝](lvgl-blur-seam.md)一共走错五次、烧了四轮固件。五个错误假设无一例外都是"读 LVGL 源码 + 手算它应该怎么走"推出来的，而每一个在真机把实际值打出来之后，几秒钟就死了。这个教训是通用的。

## 假设是关于某个计算结果的，就把那个结果打出来

tile 那次最典型。`refr_area()` 里是这么算的：

```c
uint32_t ideal_tile_size = total_buf_size / max_tile_cnt;
uint32_t area_buf_size   = lv_area_get_size(area_p) * lv_color_format_get_size(layer->color_format);
tile_cnt = (area_buf_size + (ideal_tile_size - 1)) / ideal_tile_size;
```

要手算这个，得同时拿准四个分散在别处的值：`disp->tile_cnt`、reshape 之后的 `draw_buf->data_size`、图层的颜色格式、失效区域。其中任何一个搞错，结论就翻过来。在那个函数里插一句 `esp_log_write` 就把这一整套省了：

```
refr: area 0,0..467,467 cf=18 px=2 area_sz=438048 buf_sz=438048 max_tiles=1 -> tiles=1 tile_h=468
```

注意 `lv_display_get_tile_cnt()` 返回 1 **不是同一个问题**——那是上限，不是实际块数。我当时就是拿上限当结论，才把 tile 这条路错误地排除了一轮，后来又错误地捡了回来。**打那个被推导出来的值，不是打它的输入。**

## 度量方式要和缺陷的形态对上

在渲染帧上试了三种度量才试对。

第一种，相邻行的平均绝对差。没用。这条缝的落差大概是 186 分之 4，而同一帧里前景图的边缘比它大 5~20 倍，直接把它埋了——排名最靠前的几行全是前景图自己的上下边界。

第二种，全帧二阶差分。好一些，但因为同样的原因还是吵。

第三种，**只在模糊带（前景图左右两侧的列）上算二阶差分**。模糊区域按定义就是平滑的，二阶差分天然接近零，有台阶才会跳出来。缝立刻窜到全帧均值的 11 倍、相邻行的 25 倍：

```
seam d2 468x468 avg=40 top: 233=427 234=427 92=118 | mid 232..236: 8 427 427 14 18
```

套路是这样：找一个**正确输出必然是平的**的度量，然后去看哪里不平。

另外，除了 top-N 列表，一定要把你关心的那几个坐标的数值直接打出来。细微缺陷可能挤不进前几名，而"它不在列表里"根本不能算证据——第二轮就是这么白烧了一次。

还有个小知识：单个台阶如果发生在第 `a` 行和 `a+1` 行之间，会同时抬高这两行的二阶差分。看到相邻两行都高，那是**一个**边界，不是两个。

## 先确认探针能出声

有两轮固件是白烧的，因为探针根本发不出声音。

`LV_LOG_USER` 在 `CONFIG_LV_USE_LOG` 关闭时会被整个编译掉，而这个项目里它就是关的。在 LVGL 源码里插日志要用 `ESP_LOGx` 或 `esp_log_write`。

另一次是第一版壁纸探针压根没跑到——那次开机文件系统刚被重新格式化，没有缓存壁纸，界面根本没走到壁纸页。当时那份日志不是"帧是干净的"的证据，而是"根本没有帧"。

所以在让人帮你烧一轮之前，先想清楚：假设成立时日志长什么样，不成立时又长什么样。如果两者一样，这轮就别烧。

## 排除也是进展，但别说成定位

五个假设里有四个只产出了排除、没产出修复。这是实打实的进展，该这么讲。但不能讲成诊断。

"整帧是一次画完的，所以拆分发生在别处"——这是诚实的。
在 `tiles=1` 打出来之前就说"是 tile 拆分"——这不诚实，而且我确实这么说过一次。

## 探针要一次性、要便宜

这次用到的每个探针都不到 40 行，用完就扔。两个在项目自己的代码里（`lvgl_flush`、壁纸解码路径），三个是 `device/vendor/lvgl` 里的临时改动。

改 vendor 做探针是安全的，**恰恰因为它是一次性的**（见 [vendor-patching.md](vendor-patching.md)）。但用完必须在 vendor 仓库内部 `git checkout` 还原，而且要记住：**这些改动在顶层 `git status` 里是看不见的**。
